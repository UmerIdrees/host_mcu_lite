01. Technical Inventory: What Has Been Done

Host MCU Lite (hml) is an independent, zero-dependency C11 systems library designed to bridge microcontrollers and embedded sensors directly to high-performance host servers (with native ingestion support for NVIDIA Holoscan) over standard UDP (T0) or socket-crafted RoCEv2 (T1a).

🛡️ Wire Integrity & Codec

Dual CRC-16 (CCITT) architecture protecting both the 28-byte header and 1428-byte fragment payload independently. Corrupted packets fail-closed and are dropped before state alteration.

🔄 Out-of-Order Reassembly

In-band HML_FLAG_END sequencing, gap and packet loss counters, arrival-order staging buffer, index-order zero-gap delivery, and zero-payload EOF flushing.

⚡ RoCEv2 Transport (T1a)

User-space socket crafting of standard RoCEv2 UC RDMA WRITE packets (BTH, RETH, ICRC) on UDP port 4791/14791 without requiring libibverbs on the sender side.

🧭 Control & Discovery

Autonomous 28-byte UDP beacon broadcaster on port 55100 and an 11-opcode control protocol on port 55102 (including SET_DEST, START, STOP, POKE, READBACK).

🔌 Strict Port Abstraction

7-symbol platform contract (hml_clock_us, hml_sock_*). Core contains zero platform #ifdef statements, strictly verified by compile-time linters and test suites.

🧪 Multi-Vendor Emulation

Renode scripts and vendor self-check test harnesses for STM32F4, STM32F767ZI, NXP LPC, Microchip SAM, TI TM4C, and RISC-V.

03. Wire Protocol Specifications

The wire protocol is normative and frozen as Version 1. Every multi-byte field on the wire is encoded in Big-Endian (Network Byte Order), with the sole exception of the 32-bit ICRC and T1a metadata record which use little-endian per RoCEv2 specification.

1. Path T0: Framed UDP Datagram

Every UDP datagram carries exactly one fragment. Header overhead is 28 bytes, trailing CRC is 2 bytes, and maximum payload is 1428 bytes, yielding an exact datagram size of 1458 bytes (leaving 14 bytes of slack below standard 1500-byte MTU).

84sequ32 BEMonotonic sequence number per fragment

142frag_cntu16 BETotal fragments (0 = un-signaled, rely on END flag)
168ts_usu64 BEMicrosecond source clock timestamp (monotonic)

2. Path T1a: Socket-Crafted RoCEv2 Datagram

T1a structures complete InfiniBand RoCEv2 Unreliable Connected (UC) RDMA WRITE datagrams in user-space without kernel verbs dependencies:

  • IPv4 Header (20 Bytes): IHL 5, Protocol 17 (UDP), Source IP, Destination IP, TTL 64, Checksum.
  • UDP Header (8 Bytes): Dest Port 4791 (or unprivileged test port 14791), UDP length.
  • BTH — Base Transport Header (12 Bytes):
    • OpCode = 0x2A: Transport Service UC (0b001 << 5) | RDMA WRITE (0x0A).
    • Flags = 0x00, Partition Key = 0xFFFF, Dest QP (24-bit), PSN (24-bit).
  • RETH — RDMA Extended Transport Header (16 Bytes):
    • Virtual Address (u64 BE): remote_addr + fragment_offset.
    • Remote Key (rkey) (u32 BE): Memory key configured via control plane.
    • DMA Length (u32 BE): Payload length (up to 1440 bytes).
  • Payload (N Bytes): Data written directly into the destination remote window.
  • ICRC (4 Bytes): CRC-32/IEEE computed over BTH, RETH, and Payload, transmitted in Little-Endian order.

3. T1a Out-of-Band Frame Completion (The Meta Slot)

ℹ️ How T1a Replaces In-Band EOF Flags
Because raw RDMA WRITE datagrams carry no in-band flags, a frame is declared complete by a dedicated 20-byte RDMA WRITE to VA = remote_addr + frame_size (immediately past the data window).
The 20-byte Little-Endian metadata structure contains: 
[0..3]   uint32_t magic       = 0x484D4C31 ("HML1")
[4..5]   uint16_t stream_id
[6..7]   uint16_t flags       = HML_FLAG_END
[8..11]  uint32_t frame_seq
[12..15] uint32_t frame_bytes
[16..19] uint32_t frame_crc32 = IEEE CRC-32 across the complete assembled frame
The host receiver's demux identifies this address without extra control messaging, validates the 32-bit frame CRC, and delivers the window buffer.

4. Discovery Beacon (Port 55100) & Control Protocol (Port 55102)

A device broadcasts a 28-byte beacon (HMLB) carrying UUID, capability flags, and firmware version. The host configures streaming parameters by exchanging 12-byte header control requests on port 55102:

OpcodeHexCommandPurpose
HML_OP_PING0x01Liveness ProbeEchoes back 32-bit nonce token.
HML_OP_SET_DEST0x02Program WindowTransmits 40-byte hml_dest_cfg (IP, port, QP, rkey, remote_addr, frame_size).
HML_OP_START0x04Start StreamingSignals MCU application loop to begin sensor acquisition.
HML_OP_STOP0x05Stop StreamingTransitions state back to Idle without resetting parameters.
HML_OP_RESET0x06Reset EngineFlushes buffers, closes active transport, resets sequence numbers.
HML_OP_POKE0x09Register WriteWrites a 32-bit value into a peripheral address space.

04. Step-by-Step Guide: Deploying on an Embedded Microcontroller

This section details how to compile, port, and run holoscan_mcu_lite on bare-metal ARM Cortex-M, RISC-V, FreeRTOS/lwIP, or ESP32 microcontrollers.

1

Integrate HML into Your Firmware Build

You can either use CMake add_subdirectory or add the static source files directly to your IDE project (Keil MDK, STM32CubeIDE, MCUXpresso, ESP-IDF):

Option A: CMake Drop-In (Recommended)

# Inside your firmware CMakeLists.txt
set(HML_NO_POSIX ON) # Strips all POSIX dependencies
add_subdirectory(third_party/holoscan_mcu_lite/firmware/hml_object hml_firmware)

# Link hml_core, hml_protocol, and hml_udp to your firmware target
target_link_libraries(my_firmware PRIVATE 
    hml::hml_core 
    hml::hml_protocol 
    hml::hml_udp
    my_board_port
)

Option B: Manual Source Tree Inclusion

  • Include headers: include/
  • Compile C sources: src/protocol/hml_protocol.c, src/protocol/hml_crc.c, src/core/hml_stream.c, src/core/hml_transport.c, src/transports/udp/hml_udp.c.
  • Define preprocessor flag: -DHML_NO_POSIX.
2

Implement the 7-Symbol Port Contract

Microcontrollers supply system clock and network sockets by implementing the 7 mandatory symbols in hml_port.h and hml_sock.h:

#include <hml/hml_port.h>
#include <hml/hml_sock.h>

/* 1. Monotonic microsecond clock (e.g. DWT->CYCCNT or FreeRTOS ticks) */
uint64_t hml_clock_us(void) {
    return (uint64_t)xTaskGetTickCount() * 1000ull; // Or hardware timer
}

/* 2. Socket creation (lwIP UDP PCB example) */
hml_status hml_sock_udp_create(hml_sock_t **out, uint32_t bind_ip, uint16_t bind_port, bool bcast) {
    struct udp_pcb *pcb = udp_new();
    if (!pcb) return HML_ERR_NOMEM;
    if (bind_port != 0) {
        ip_addr_t ip;
        ip_addr_set_any(false, &ip);
        udp_bind(pcb, &ip, bind_port);
    }
    *out = (hml_sock_t *)pcb;
    return HML_OK;
}

/* 3. Set remote target */
hml_status hml_sock_set_dest(hml_sock_t *s, uint32_t ip, uint16_t port);

/* 4. Non-blocking send: MUST return HML_ERR_AGAIN on buffer exhaustion */
hml_status hml_sock_send(hml_sock_t *s, const uint8_t *buf, size_t n);

/* 5. Receive datagram */
hml_status hml_sock_recv(hml_sock_t *s, uint8_t *buf, size_t cap, size_t *out_n, int timeout_ms);

/* 6. Close socket */
void hml_sock_close(hml_sock_t *s);
🚨 Critical Contract Obligation
If hml_sock_send() would block or cannot allocate a DMA descriptor, you must return HML_ERR_AGAIN. If your port returns HML_OK for a dropped packet, the sequence numbers will desynchronize, causing the host to discard entire frames.
3

Avoid the 2 MiB Heap Trap (Zero-Heap MCU Reassembly)

If your MCU also receives packets, never call hml_reasm_open(..., 0) as it attempts to allocate 2 MiB of dynamic memory! Instead, use the newly implemented static caller-buffer API:

#include <hml/hml_reasm.h>

#define MCU_MAX_FRAME 4096

static uint8_t g_staging_buf[MCU_MAX_FRAME];
static uint8_t g_gather_buf[MCU_MAX_FRAME];
static uint8_t g_reasm_ctx_mem[2048]; // Sized via hml_reasm_ctx_size()

hml_reasm_ctx_t *reasm = NULL;
hml_status st = hml_reasm_open_buffers(&reasm, g_reasm_ctx_mem, sizeof(g_reasm_ctx_mem),
                                      g_staging_buf, g_gather_buf, MCU_MAX_FRAME);
/* Result: Zero malloc calls. Fully deterministic memory usage. */
4

Write the Sensor Streaming Loop

#include <hml/hml_stream.h>
#include <hml/hml_transport.h>
#include "hml_udp_priv.h"

void sensor_stream_task(void *pvParameters) {
    /* 1. Register UDP Transport */
    hml_udp_register();
    const hml_xport_ops *ops = hml_transport_lookup("udp");

    /* 2. Configure Destination */
    hml_dest_cfg dest;
    memset(&dest, 0, sizeof(dest));
    dest.kind = HML_XPORT_UDP;
    dest.ipv4 = 0xC0A80164; // 192.168.1.100 (Host Server)
    dest.udp_port = 55101;  // Host Data Port
    dest.frame_size = 8192; // 8 KiB sensor frame

    hml_xport_t xport;
    xport.ops = ops;
    ops->open(&xport, &dest, 1);

    /* 3. Open Stream Framer */
    hml_stream_cfg scfg;
    memset(&scfg, 0, sizeof(scfg));
    scfg.stream_id = 1;
    scfg.max_frame_bytes = 8192;
    scfg.seq_start = 0;
    
    hml_stream_t *stream = NULL;
    hml_stream_open(&stream, &scfg, &xport);

    uint8_t sensor_buffer[8192];

    while (1) {
        acquire_sensor_data(sensor_buffer, sizeof(sensor_buffer));

        size_t offset = 0;
        bool is_first = true;
        
        while (offset < sizeof(sensor_buffer)) {
            size_t chunk = sizeof(sensor_buffer) - offset;
            if (chunk > HML_MAX_FRAG_PAYLOAD) chunk = HML_MAX_FRAG_PAYLOAD;
            
            bool is_last = (offset + chunk == sizeof(sensor_buffer));
            
            // Loop with backoff if socket queue is full
            while (hml_stream_send_frag(stream, sensor_buffer + offset, chunk, 
                                        is_first, is_last, hml_clock_us()) == HML_ERR_AGAIN) {
                vTaskDelay(pdMS_TO_TICKS(1));
            }

            offset += chunk;
            is_first = false;
        }

        vTaskDelay(pdMS_TO_TICKS(10)); // 100 Hz frame rate
    }
}

05. Step-by-Step Guide: Deploying on Servers with RDMA NICs

This section details how to receive and demultiplex incoming sensor streams on Linux host servers equipped with Mellanox ConnectX NICs or using the built-in Soft-RoCE (rdma_rxe) kernel stack.

1. Server & Network Tuning

Physical RoCEv2 Infrastructure

  • NIC: Mellanox ConnectX-5, ConnectX-6 Dx, or ConnectX-7.
  • RoCE Mode: Force RoCEv2 (UDP port 4791).
    cma_roce_mode -d mlx5_0 -p 1 -m 2
  • Lossless Fabric: Enable PFC (Priority Flow Control) on Priority 3 and DSCP-to-PFC mapping on both top-of-rack switches and server interfaces.
  • MTU: Verify standard MTU 1500 or Jumbo Frames 9000 match MCU MTU.

OS Kernel Socket Buffers

Because the Linux kernel defaults to small receive buffers, high-rate UDP streams will drop packets before user-space polls. Run as root:

sysctl -w net.core.rmem_max=67108864
sysctl -w net.core.rmem_default=33554432
sysctl -w net.core.netdev_max_backlog=10000

2. Building the Host Binaries

# On your Linux Host Server:
git clone <repo_url> holoscan_mcu_lite
cd holoscan_mcu_lite

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DHML_WARNINGS_AS_ERRORS=ON
cmake --build build -j$(nproc)

# Run full self-test suite (62 tests):
ctest --test-dir build --output-on-failure

If you are developing without a physical ConnectX card, use the repository's Soft-RoCE test lab. It sets up two isolated network namespaces (hml-a and hml-b) bound to software RDMA devices:

4. Running the RoCEv2 Demux Receiver

The host RoCE receiver binds to UDP port 14791 (or privileged port 4791) and processes BTH/RETH writes into an internal memory window:

# Start the RoCE receiver listening on port 14791:
./build/host/roce_demux/hml_host_roce \
    --port 14791 \
    --window-base 0x100000 \
    --window-len 65536 \
    --frame-size 9000 \
    --rkey 0xDEADBEEF \
    --verbose

# In another terminal, stream synthetic RoCE frames to it:
./build/adapters/synthetic/hml_gen \
    --dest-ip 127.0.0.1 \
    --port 14791 \
    --xport rocev2 \
    --frames 10 \
    --size 9000 \
    --rkey 0xDEADBEEF \
    --window-base 0x100000

Both receiver and sender calculate and display matching IEEE CRC-32 checksums, proving bit-level integrity through the RoCE demux.

06. NVIDIA Holoscan AI Pipeline Integration

To ingest HML frames into an NVIDIA Holoscan execution graph, we deploy a Custom Holoscan C++ Operator (HmlReceiverOp). This avoids reverse-engineering hololink while delivering full zero-copy/pinned CUDA acceleration.

Complete C++ Holoscan Operator Implementation

#include <holoscan/holoscan.hpp>
#include <cuda_runtime.h>
#include <hml/hml_reasm.h>
#include <hml/hml_sock.h>

namespace holoscan::ops {

class HmlReceiverOp : public Operator {
 public:
  HOLOSCAN_OPERATOR_FORWARD_ARGS(HmlReceiverOp)

  HmlReceiverOp() = default;

  void setup(OperatorSpec& spec) override {
    spec.param(port_, "port", "Port", "UDP data port", static_cast<uint16_t>(55101));
    spec.param(max_frame_bytes_, "max_frame_bytes", "Max Bytes", "Buffer size", static_cast<size_t>(1048576));
    spec.param(device_id_, "device_id", "GPU Device ID", "CUDA GPU ID", 0);
    spec.output<holoscan::TensorMap>("out_tensor");
  }

  void initialize() override {
    Operator::initialize();

    // 1. Create Non-blocking UDP Socket
    hml_sock_udp_create(&sock_, 0, port_.get(), false);

    // 2. Open Reassembler
    hml_reasm_open(&reasm_, max_frame_bytes_.get());
    hml_reasm_set_eof_cb(reasm_, on_eof_static, this);

    // 3. Allocate CUDA Device Memory and Stream
    cudaSetDevice(device_id_.get());
    cudaMalloc(&d_gpu_buffer_, max_frame_bytes_.get());
    cudaStreamCreate(&stream_);
  }

  void compute(InputContext&, OutputContext& op_output, ExecutionContext&) override {
    uint8_t rx_buf[HML_MAX_FRAG_SIZE];
    size_t rx_bytes = 0;

    // Drain socket queue
    while (hml_sock_recv(sock_, rx_buf, sizeof(rx_buf), &rx_bytes, 0) == HML_OK) {
      if (rx_bytes > 0) {
        frame_ready_ = false;
        hml_reasm_feed_datagram(reasm_, rx_buf, rx_bytes);

        // When a frame completes, transfer to GPU and emit
        if (frame_ready_ && last_frame_size_ > 0) {
          cudaMemcpyAsync(d_gpu_buffer_, last_frame_data_, last_frame_size_,
                          cudaMemcpyHostToDevice, stream_);
          cudaStreamSynchronize(stream_);

          // Wrap as Holoscan Tensor
          std::vector<int64_t> shape = {static_cast<int64_t>(last_frame_size_)};
          auto tensor = std::make_shared<Tensor>(d_gpu_buffer_, shape, DLDataType{kDLUInt, 8, 1});
          
          TensorMap out_map;
          out_map["sensor_raw"] = tensor;
          op_output.emit(out_map, "out_tensor");
        }
      }
    }
  }

  void stop() override {
    if (d_gpu_buffer_) cudaFree(d_gpu_buffer_);
    if (stream_) cudaStreamDestroy(stream_);
    if (reasm_) hml_reasm_close(reasm_);
    if (sock_) hml_sock_close(sock_);
  }

 private:
  static void on_eof_static(void *ctx, uint16_t stream_id, uint32_t seq,
                           const uint8_t *frame, size_t n, const hml_frame_hdr *hdr) {
    auto *self = static_cast<HmlReceiverOp*>(ctx);
    self->last_frame_data_ = frame;
    self->last_frame_size_ = n;
    self->frame_ready_ = true;
  }

  Parameter<uint16_t> port_;
  Parameter<size_t> max_frame_bytes_;
  Parameter<int> device_id_;

  hml_sock_t *sock_{nullptr};
  hml_reasm_ctx_t *reasm_{nullptr};
  void *d_gpu_buffer_{nullptr};
  cudaStream_t stream_{nullptr};
  const uint8_t *last_frame_data_{nullptr};
  size_t last_frame_size_{0};
  bool frame_ready_{false};
};

} // namespace holoscan::ops

🕒 The Clock-Domain Trap (Latency Measurements)
Latency in hml_reasm is computed as delta = hml_clock_us() - ts_us. If the sender and receiver are on separate boards without hardware PTP synchronization, their clocks have different epochs and drift. The library detects this automatically: if ts_us > now, it records the sample as skew and excludes it from the p99 histogram to avoid reporting fabricated metrics.
